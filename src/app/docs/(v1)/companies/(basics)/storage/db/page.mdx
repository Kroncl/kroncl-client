# 1. База данных организации

<span className={styles.underline}>Хранилище данных организации / База данных</span> используется для хранения текстовых данных организации.

Информация об использовании хранилища данных (базы данных) организации доступна в разделе <span className={styles.underline}>«Хранилище»</span> пространства организации.

База данных организации имеет <span className={styles.underline}>лимит объёма данных</span>, измеряемого в мегабайтах. Каждый тарифный план имеет своё значение лимита,
при достижении которого учётная система перейдёт в <span className={styles.underline}>режим чтения</span>, запрещающий создание, обновление или удаление объектов в учётной системе.

Вы в любой момент можете получить актуальную информацию об использовании базы данных на странице просмотра информации о хранилище компании. Здесь представлена вся необходимая
информация:

- объём данных, хранящихся в БД
- процентное отношение использованных к оставшимся ресурсам БД (полоса-индикатор)
- лимит текущего тарифного плана
- размер индексов БД организации
- размер таблиц
- количество таблиц
- количество активных подключений
- количество строк в таблицах БД организации

# 2. Распределение по модулям

Кроме основных данных о базе данных организации, вам доступна информация о распределении ресурсов по модулям учётной системы. Здесь вы можете увидеть
столбчатую диаграмму модулей, в которой каждый столбец соответствует каждому модулю платформы. <Link href='/docs/companies/modules' className={styles.link}>Подробнее о модулях Kroncl.</Link>

При наведении на соответствующий столбец вы увидите потребление ресурсов базы данных по модулям. Такая детализация
позволяет вовремя выявлять самые нагруженные модули, используемые вашей компанией.

# 3. Оптимизация

Вопреки распространённому мнению, при достижении лимитов БД компании далеко не всегда целесообразно сразу же повышать уровень тарифного плана.
В большинстве случаев оптимизация хранилища данных организаций достигается очисткой логов. <Link href='/docs/companies/logs' className={styles.link}>Подробнее о логах.</Link>
